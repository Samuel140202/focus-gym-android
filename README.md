# FOCUS GYM

FOCUS GYM is an academic Android application developed as a university project. It combines workout and routine management with a simple PHP/MySQL authentication backend.

## Main features

- User login with administrator and user roles
- Administrator user creation and deletion
- Workout routine creation and editing
- Exercise selection and routine details
- Workout session flow with rest/timer screens
- Session history and statistics
- Workout reminders and notifications
- Language support in the Android application

## Technologies

- Java
- Android Studio / Android SDK
- MySQL
- PHP
- XAMPP / Apache
- phpMyAdmin

## Repository structure

- `app/` — Android application source code and resources
- `backend/` — PHP files used by the login/admin backend
- `database/` — SQL script for the authentication database
- `gradle/` — Gradle wrapper files

## Local backend setup

1. Install and start Apache and MySQL using XAMPP.
2. Create/import the database using `database/script_bd_login_app.sql`.
3. Copy the contents of `backend/` into a folder served by Apache (the original project used a `login` folder).
4. Check the database settings in `backend/conexion.php`. The included values reflect the default local XAMPP development setup and should not be used for a production server.
5. In `LoginActivity.java` and `AdminActivity.java`, set `DEVICE_BASE_URL` to the local IP address of the computer running XAMPP when testing on a physical Android device. The repository contains `192.168.1.100` only as an example private-network address.
6. For the Android emulator, the project uses `10.0.2.2` to reach the host computer.

Example:

```java
private static final String DEVICE_BASE_URL = "http://YOUR_LOCAL_IP:8080/login/";
```

## Security note

This project was created for academic/local-network use. Passwords are stored as hashes by the PHP backend, and login verification uses PHP's password verification functions. Before deploying this architecture to a public production environment, additional security hardening would be required, including HTTPS, protected configuration/secrets, production database credentials, and server-side deployment controls.
